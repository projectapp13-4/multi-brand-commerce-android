Related authority: [screen inventory](P3-00-INFORMATION-ARCHITECTURE-AND-SCREEN-INVENTORY.md), [data ownership](P3-00-DATA-OWNERSHIP-AND-PERSISTENCE.md), and [product/slice readiness](P3-00-PRODUCT-SCOPE-AND-SLICE-READINESS.md).

## Shared flow rules

- A remote failure never turns an empty screen into fake data or a terminal startup block.
- Retry is shown only when the action is idempotent or the app can reconcile the outcome. Mutations first refresh or re-read authoritative state when outcome is ambiguous.
- Cancellation is a normal state for filters, hosted account authorization, checkout, external pages, forms, and confirmations. It preserves the last valid state unless the user explicitly chose to clear it.
- Process restoration persists only stable non-sensitive identifiers and approved preferences. Tokens, cart IDs, checkout URLs, addresses, orders, raw external URIs, and server messages never enter `SavedState`.
- Offline browsing uses only an approved bounded cache and labels stale/unavailable-to-buy state. No queued customer/cart/address/profile/deletion mutation exists unless its slice explicitly proves an authenticated idempotent queue.
- Terminal auth failure removes protected back-stack entries and applies cart detachment/quarantine before signed-out UI appears.
- Every error is typed and redacted. User copy explains what can be done next, not raw HTTP/GraphQL/SDK details.

## Cart ownership transition table

| Event | Current state | Required result |
|---|---|---|
| First valid cart create while signed out | none | `Anonymous` |
| Sign in with an anonymous cart | `Anonymous` | Reconcile/associate once; success `CustomerAssociated`; failure retains a safe explicit state without duplicating lines |
| Sign out or terminal expiry | `CustomerAssociated` | `DetachPending`; on confirmed buyer-identity removal become `Anonymous`; otherwise `Quarantined` |
| Launch checkout | `Anonymous` or `CustomerAssociated` | Refresh and enforce current market/buyer identity; `DetachPending`/`Quarantined` cannot checkout |
| Genuine checkout completion | any eligible state | Clear only completed cart ID/state; do not touch wishlist/history |
| Cancel/decline/transient checkout failure | eligible state | Retain authoritative cart and ownership |
| Definitive invalid/expired cart | any | Clear protected reference, show explicit recovery, create replacement only through a deliberate user flow |
| Environment/market switch | any | Never carry capability/price state across environment; market policy reconciles or quarantines before exposure |

## Flow acceptance boundary

P3-00 accepts these contracts as implementation-ready specifications. It does not claim browser, device, Shopify, Firebase, cart, checkout, or production runtime proof. Each owning slice must replace the corresponding proof surface, implement only its accepted flow, and attach test/device evidence in proportion to the new behavior.
